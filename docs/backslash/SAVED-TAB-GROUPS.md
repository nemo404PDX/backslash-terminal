# Saved tab groups

[Project entry point](README.md) | [Feature scope](FEATURES.md) | [Roadmap](ROADMAP.md)

## Saving and reopening

A **Groups** dropdown sits beside the new-tab button. **Save current tabs as group** records a named terminal layout; choosing a saved group appends fresh terminals to the current window and restores saved tab order, split directions/ratios and focused tab/pane. Existing tabs are preserved. Settings > Startup > Saved tab groups supports name/folder-mode updates and deletion through the existing Settings clone: **Update group/Delete** changes the draft, **Save** persists, and **Reset** discards unsaved edits. Closing Settings without saving leaves the live catalog unchanged.

Saving accepts one or more terminal tabs, including one tab with splits. Standalone Settings tabs are skipped and stay open with their unsaved edits intact. Mixed or unsupported nonterminal pane layouts are rejected rather than partially saved. With no eligible terminal tabs, “No terminal tabs to save” always explains why saving is blocked. A canceled dialog writes nothing. Failed writes leave the live catalog/draft unchanged, and settings changes during the form abort saving rather than overwrite a newer object.

## Persistence and identity

`backslash.savedTabGroups` is a versioned object in Backslash's existing isolated settings.json, not the automatic state.json window/session history. Version 1 stores a stable group GUID, name, folder mode, focused tab and ordered restricted pane-layout steps. Profile references contain GUID plus source; changing a display name does not change identity. Rename retains group ID. Delete/recreate receives a new ID even with the same name. Names are unique case-insensitively, 1-80 UTF-16 characters without controls; bounds are 50 groups, 32 tabs/group, 64 panes/tab, 512 layout steps/tab and 1024 panes across the catalog.

Steps allow only new tab, manual split, relative layout traversal and pane focus. No terminal input/output, command lines, environment snapshots, passwords, session/content IDs, scrollback, runtime tab titles or runtime color/zoom overrides are saved. Reopening uses the current referenced profile's normal launch configuration. It creates fresh local terminals/connections; that profile's own configured command/RemoteCommand may have its own behavior, but groups do not add remote process persistence.

Unknown versions/fields or invalid data remain raw through unrelated Settings copies/saves. Opening/editing that catalog is blocked with an explanation; it is never deserialized as arbitrary startup actions. The catalog is outside settings telemetry. The schema lives in [profiles.schema.json](../../backslash/doc/cascadia/profiles.schema.json), with runtime validation/allowlisting in [SavedTabGroups.h](../../backslash/src/cascadia/TerminalSettingsModel/SavedTabGroups.h).

Group template ID is separate from runtime tab/pane/connection or remote session identity. Saved focus IDs are recipe-relative pane ordinals, not durable attachment IDs. Capture does not alter current runtime identities, and reopening/duplication never reuses a saved content/session ID. Tab tear-out and cross-process identity/control handoff remain upstream/future transport concerns; this slice makes no new remote ownership promise.

## Folder modes and trust limits

**Profile default folders** stores no folder snapshots and leaves starting-directory overrides empty on reopen, so current profile defaults apply. **Folders captured at save** stores only available, absolute local drive paths from an actual client report in supported direct cmd/PowerShell profiles. A new `ReportedWorkingDirectory` control property distinguishes the initial profile directory seed from a later report. Reports remain advisory metadata from cooperative local applications, not authenticated process/cwd evidence; the supported local-profile/path policy is conservative and must not be treated as a universal trust boundary.

SSH client's local cwd does not establish remote cwd. WSL/SSH profiles, script/remote wrappers, unsupported/unreported paths, UNC/relative/Linux paths and paths containing percent expansion are not captured in v1. Saving reports the number of panes using defaults. On reopening captured mode, missing/unsupported/unreported folders produce an explicit **Open with profile defaults / Cancel** choice before any tab is launched. Profile-default launch errors use the existing terminal connection error path. Folder snapshots never auto-update; changing folder mode later does not capture current locations or fabricate omitted snapshots.

## Launch safety and upstream reuse

[Pane::BuildStartupActions](../../backslash/src/cascadia/TerminalApp/Pane.cpp) already reconstructs the split tree; an optional per-pane factory now provides clean group arguments without changing ordinary move/persist behavior. [Tab::BuildStartupActions](../../backslash/src/cascadia/TerminalApp/Tab.cpp) preserves layout/focus traversal; capture copies only the group allowlist. [TerminalPage](../../backslash/src/cascadia/TerminalApp/TerminalPage.cpp) preflights every exact GUID/source against active profiles before launch, with no default-profile substitution. A missing/disabled/replaced profile blocks opening and identifies its GUID. Profiles requiring elevation in a different window are rejected rather than destroying the group layout.

Opening temporarily appends tabs regardless of the ordinary new-tab placement preference, without changing that preference. Each subsequent layout action reselects its exact newly created tab, so an interleaved user selection cannot split an existing tab. If a new group tab is closed or a referenced profile changes during restoration, opening stops with an explanation and retains already created tabs. Runtime launch failure can leave a partial group; existing tabs are never rolled back/replaced. Final focus returns to the saved group tab/pane. No real SSH connection is required for model tests.

## Saved-group startup

Settings > Startup now keeps **Default profile** as the ordinary new-tab/window profile and adds **On startup > Start with: Default profile / Saved group**. Default profile remains the default startup mode. Saved group reveals a searchable, group-only **Startup group** picker. Choose a listed result, then **Save**; typing a search alone does not select a group. The existing Settings clone and **Reset** protect unsaved edits.

Persistence uses `backslash.startupWithSavedGroup` (boolean, default `false`) and `backslash.startupGroup` (string containing a stable group GUID, default empty). `defaultProfile` and the previous-session restoration default are unchanged. Turning the mode off retains the selected ID. Rename keeps selection; deletion or recreation with the same name does not retarget it. Suggestions carry IDs and validate the exact ID again when selected.

The saved starting group applies to eligible ordinary initial launches and to an ordinary window request when the resident process has no app windows. Adding another window while one exists does not replay it. Explicit CLI/profile/actions, configured startup actions, connection/content requests and restored layouts keep their existing precedence. See [resident startup and background lifetime](STARTUP-GROUP-REOPEN.md).

Startup reuses SavedTabGroups::Build and preflights every active profile's exact GUID/source and elevation compatibility. Missing/invalid catalog/group, deleted/disabled/replaced profile or incompatible elevation opens **one default-profile tab with a closeable warning**. Successful startup creates only the group tabs/panes, restores its order, splits and saved focus, and adds no default tab. The first tab is created synchronously before window initialization; subsequent layout steps yield on the UI thread and reselect their exact newly created tab. Changes during restoration stop opening and retain created tabs; ordinary runtime connection errors remain visible without a rollback promise.

Captured-folder startup validates supported local folders before any terminal is launched. Missing/unsupported/unreported folders show an owned **Startup group folders** prompt: **OK** opens the group with profile-default folders for those panes; **Cancel** opens one default-profile tab with a notice. Cancel is the default button. This prelaunch native prompt is necessary because the app frame is cloaked until its first tab exists; the menu opener still uses its XAML folder confirmation. Elevated default-profile fallback also reports the notice before handing off. Groups remain manually maintained recipes: startup and Close All do not save or update their layouts, and no last-workspace recovery is added.

Source: [StartupGroupPolicy.h](../../backslash/src/cascadia/TerminalSettingsModel/StartupGroupPolicy.h), [TerminalWindow](../../backslash/src/cascadia/TerminalApp/TerminalWindow.cpp), [WindowEmperor](../../backslash/src/cascadia/WindowsTerminal/WindowEmperor.cpp), [TerminalPage](../../backslash/src/cascadia/TerminalApp/TerminalPage.cpp), [Launch editor](../../backslash/src/cascadia/TerminalSettingsEditor/Launch.xaml). The named/localized mode and group containers occur in the generated Settings search index. Search navigation does not change the mode or selection. The picker is collapsed in Default profile mode.

## Group-name editor

The group-name editor uses a TeachingTip with delayed input focus, following the existing [window-renamer pattern](../../backslash/src/cascadia/TerminalApp/AppActionHandlers.cpp#L994). TextBox input inside ContentDialog is unsuitable in this XAML Islands host.

The editor closes the Groups menu before opening, focuses the name field after sufficient layout and revokes its focus hook once successful. The text field keeps native editing and its text context menu. Save is enabled by existing name validation; Enter requires a keydown in this editor so the menu's opening Enter keyup cannot save it. Escape/Cancel/close cancel without writing. Tab navigation cycles through the form. After closing, focus returns to the active terminal; reopening constructs a fresh form. Unloading the host cancels the pending editor and its temporary visual/event handlers are removed. The existing window/tab rename and Settings group-name fields remain unchanged.

The input popup is a TeachingTip rather than a modal ContentDialog. Other page interaction is possible while it is open; the existing group-operation guard, settings-object change check and terminal-only capture checks still govern saving. No new input is forwarded to the shell by this form and no terminal key/TSF interception code was changed. The separate folder-fallback confirmation still uses ContentDialog because it contains no text input.

## Startup picker behavior

The old picker used a custom StartupGroupEntry with `TextMemberPath="Name"` and rebuilt/cleared its ItemsSource synchronously inside QuerySubmitted. TextMemberPath asks XAML to resolve the selected item's display property dynamically; the custom type lacked the editor's established stringable suggestion behavior. Both unsafe paths were removed. The picker now uses existing EnumEntry items in an IInspectable collection, typed display templates, UpdateTextOnSelect=false, and explicit display text after selection. Query submission revalidates the exact GUID against the current catalog, changes only the Settings draft and does not rebuild the list while AutoSuggestBox is processing the item. Refresh guards restore their prior state; empty typed queries and stale/deleted/recreated suggestions preserve the saved ID. Invalid selected IDs leave current suggestions available for repair. No group/catalog migration or overwrite was introduced.

[Microsoft's TextMemberPath reference](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.autosuggestbox.textmemberpath?view=winrt-26100) describes the selected-item property-path behavior. The correction follows the repository's existing object-suggestion controls, rather than relying on dynamic reflection of the new class. [StartupGroupPolicy](../../backslash/src/cascadia/TerminalSettingsModel/StartupGroupPolicy.h) supplies the picker/selection logic used by [Launch.cpp](../../backslash/src/cascadia/TerminalSettingsEditor/Launch.cpp).

## Startup picker layout

Suggestion containers stretch, and complete group names wrap without an ellipsis/line-count cap. Each row has a full-name tooltip and accessible name; the selected field has a tooltip bound to its native Text property. Mode/group descriptions and selection status are concise. Status lives below the field inside the conditional card, rather than repeating launch-precedence prose outside it. All stable GUID, search/selection guards, Settings draft Save/Reset and startup behavior are unchanged.

## Settings reminder and draft preservation

Capture filters standalone Settings tabs from the live left-to-right tab order, retains every eligible terminal tab and its complete split tree, and maps the focused terminal to its position in that filtered list. When Settings is focused, the saved group deterministically focuses the first eligible terminal tab. The live selection, tabs and sessions are not removed/reordered by saving. A terminal mixed with Settings or another nonterminal pane, a split-only Settings layout, an unsupported pane or an incomplete layout remains a cannot-save error; no content is silently dropped. Single terminal tabs and their splits were already supported and remain supported.

When terminal tabs and standalone Settings are present, a TeachingTip says **Settings tabs won’t be included in this group.** It offers **Continue**, **Cancel** and **Don’t show this again**. Continue opens the existing group-name editor; Cancel/close/Escape changes no group, tabs or preference. The reminder appears at most once in a save attempt, including revalidation when tabs change during the form. Tab navigation cycles through the controls; Enter uses a keydown/keyup pair so the menu-opening keyup cannot continue accidentally. Focus returns to the current tab, and temporary handlers/visuals are removed on close/unload.

The checked preference is committed only after the group itself saves successfully, to the isolated adjacent `state.json` key `backslash.savedGroupSettingsNoticeDismissed` (false by default). Canceling the name editor or a failed group write does not persist it. Only this informational reminder is hidden: Settings-only/zero-terminal, unsupported content, invalid names/catalogs, folder notices and write/conflict errors remain visible. Reset Application State can reset this local preference; ordinary Settings Reset does not discard a successfully saved group or alter notice state.

Saving a group now preflights open Settings drafts for catalog/name/bounds conflicts before writing. Successful group-only additions merge into the **same Settings clone** while keeping unsaved profile/global edits, group renames/deletions, page controls, navigation and text intact. Repeated identical watcher notifications after that addition do not recreate the clone or duplicate a GUID. Explicit Reset still makes a fresh copy of the latest saved source, retaining the added group and discarding unsaved edits as requested. Other settings reloads retain the existing normal path. An addition conflicting with another window's draft keeps that draft and blocks its Save until the conflict is resolved or Reset; it does not silently overwrite either recipe. The group management list can refresh on navigation rather than force a page rebuild while editing.

[GroupSavePolicy.h](../../backslash/src/cascadia/TerminalSettingsModel/GroupSavePolicy.h) owns the tested eligibility, focus, notice gating and append merge rules. [TerminalPage](../../backslash/src/cascadia/TerminalApp/TerminalPage.cpp) classifies actual pane roots and uses those rules; [MainPage](../../backslash/src/cascadia/TerminalSettingsEditor/MainPage.cpp) preserves the editing clone through the model's bounded equality API. [ApplicationState](../../backslash/src/cascadia/TerminalSettingsModel/ApplicationState.h) stores the specific reminder flag. The existing group-name TeachingTip input body and all prior picker/reset/layout fixes remain included.

## Limitations and contributor checks

Saved groups reopen fresh sessions; they do not preserve running processes, remote sessions or unsaved editor buffers. Captured folders follow the supported local-path policy above. Native keyboard, screen-reader, IME, DPI, popup layout and focus-restoration coverage remains incomplete.

Dated crash investigations, automated results and reported interactive acceptance are retained in [saved-group operational verification](../dev/FEATURE-RECORDS.md#saved-group-operational-verification).
