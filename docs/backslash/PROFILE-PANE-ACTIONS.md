# Terminal-pane profile actions

This uncommitted implementation adds two short entries to the tab context menu. **Split with profile** appears directly below the existing one-click Split command. **Relaunch with profile** is grouped with session restart operations. Each submenu lists available profiles with their icons. The clicked tab's focused terminal leaf is captured when the menu opens; Settings, Transfers, other native views, parent selections, pinned tabs, read-only content and in-progress operations are not eligible. The actions never search for another terminal when a native view is focused.

Split creates another terminal using the chosen profile and the existing automatic split sizing. It preserves the current session. Relaunch replaces only the captured leaf's content, keeping its pane identity, surrounding split tree, ratios and siblings. It applies the selected profile's full launch configuration and appearance. Old command-line, working-directory and temporary appearance overrides are not carried across profiles. In particular, a local directory is not silently inherited by an SSH launch.

Relaunch initially asks for confirmation, names the target profile, defaults to Cancel and warns that running work may be interrupted. For SSH, closing the local connection does not guarantee that remote jobs terminate. The unchecked **Don't ask again when relaunching a pane** choice is scoped to this feature. It is saved only after a confirmed, validated, committed relaunch, using the existing conflict-safe settings writer. Cancel and stale/invalid targets do not save it. A dirty, busy or stale Settings editor anywhere in the process prevents this automatic preference write; the relaunch can still complete, but the warning remains enabled and an explanatory notice appears. **Settings > Interaction > Confirm before relaunching a pane** restores the warning. Other close warnings are independent.

The implementation revalidates the captured content and chosen active profile after confirmation. Removing/replacing the leaf or profile cancels the action. A per-tab operation guard and the existing close-request gate prevent duplicate relaunches and overlapping deliberate close/move operations during confirmation. Unelevated windows reject profiles requiring elevation rather than silently opening another window.

The replacement is constructed before old-session teardown. Construction/attachment failure restores the original content; teardown happens once after the new content is wired. After commit, subsequent shell or SSH startup/authentication failure belongs to the new session and cannot restore the ended process. Failed replacement connections remain visible; no fallback shell or automatic old-profile restart is used. No real user session has been terminated during automated verification.

Saved Groups already capture each terminal leaf's profile GUID/source and split layout. A relaunched leaf owns the chosen profile identity, so a later Group save records that identity. Group restore starts new sessions and may authenticate again; it does not preserve live processes or credentials. Captured local-folder rules and rejection of unavailable exact profile identities remain unchanged. Transient appearance-only changes and arbitrary command overrides are not added to the Group format by this feature.

Profile-specific split shortcuts were already supported by `splitPane`. The new submenu displays an actually assigned shortcut only when its binding matches the chosen profile, automatic direction, half split and absence of extra launch overrides. No global shortcuts are assigned. There is no new relaunch command-line syntax or keyboard action in this slice. The original direct Split remains available.

Background sessions remain separately paused. Relaunch does not detach old work, retain it in a background registry or implement automatic restart. Transfers behavior is independent.
