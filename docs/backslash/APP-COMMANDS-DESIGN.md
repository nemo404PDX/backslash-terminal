# Internal app commands - future design

## Status and intended ownership

Documentation only. A keyboard-accessible Backslash command field/palette should expose local application actions. Slash syntax is preferred for familiarity over colon/backslash, but the prefix, grammar and defaults are not finalized. Candidate names include `/help`, `/settings`, `/groups`, `/ssh`, pane commands and future `/files`. No slash interception, transfer backend or remote persistence is implemented in the saved-groups slice.

Start with a dedicated, visibly labeled **Backslash app commands** field. Its text belongs to the local application, including while the selected terminal is connected by SSH. Display action/target and whether submission opens a connection before Enter. Preview, filtering and completion must not connect, execute, transfer, change settings or run remote queries. Explicit Enter dispatches a validated typed action once; Escape dismisses/cancels without sending text to the shell and restores the previous terminal/pane focus. Tab/arrow completion and focus traversal require configurable, accessible bindings and conflict review. Ordinary shell editing/history remains intact.

Unknown or malformed commands in this dedicated field show an app error and retain editable text; they never fall through to local or remote shell execution. Provide a deliberate **send literally to terminal** escape/action with visible target and exact text preview. Its syntax remains open. Later optional inline slash recognition needs a verified local command buffer and input ownership, not output scraping or a leading-character heuristic. Absolute Unix paths can execute programs, and an exact recognized name such as `/help` can also name a real executable. Decide literal escaping, mode indication, pasted-text behavior and collisions before enabling inline interception. Never intercept password prompts, full-screen programs, scripts/multiline paste, unverified/pass-through modes or untrusted terminal output.

## Reuse actual upstream actions

The existing [CommandPalette](../../backslash/src/cascadia/TerminalApp/CommandPalette.cpp) filters commands and raises `DispatchCommandRequested`; `TerminalPage::_OnDispatchCommandRequested` in [TerminalPage.cpp](../../backslash/src/cascadia/TerminalApp/TerminalPage.cpp) forwards their `ActionAndArgs` through `_actionDispatch->DoAction`. [AppKeyBindings::TryKeyChord](../../backslash/src/cascadia/TerminalApp/AppKeyBindings.cpp) uses the same dispatch, and [ShortcutActionDispatch](../../backslash/src/cascadia/TerminalApp/ShortcutActionDispatch.cpp) routes typed actions to handlers. [ActionMap](../../backslash/src/cascadia/TerminalSettingsModel/ActionMap.cpp), [Command](../../backslash/src/cascadia/TerminalSettingsModel/Command.cpp) and [ActionArgs](../../backslash/src/cascadia/TerminalSettingsModel/ActionArgs.idl) provide names, bindings and typed arguments.

The palette also has a separate command-line mode: `_dispatchCommandline` raises `CommandLineExecutionRequested`, and TerminalPage wraps `ExecuteCommandlineArgs`. This existing path is not a proof of a safe new slash grammar or shell-buffer ownership. Keep app syntax parsing separate from shell syntax and Windows Terminal CLI syntax. Do not treat an unknown app command as ExecuteCommandline or SendInput.

Menus, shortcuts and app commands should resolve to the same typed action and validation path. Existing groups currently use `_SaveCurrentTabGroup` / `_OpenSavedTabGroup` directly from their dropdown; registering safe group-ID actions is a future refactor before exposing slash commands, not an already implemented capability. Resolve group/profile arguments by stable IDs after user selection; names are display/completion labels and rename must not redirect a stale preview. Complete action names plus eligible group/profile arguments without network side effects. Define quoting for spaces/Unicode, literal quotes, paths, `--`, missing/extra arguments and ambiguity. Do not execute argument strings with a shell parser.

## Native pane minimum

A tab is a workspace containing a split tree, not two tabs displayed side by side. Native splits do not require tmux. [Pane](../../backslash/src/cascadia/TerminalApp/Pane.cpp) already implements split geometry, directional navigation, resizing, removal/rebalancing and startup reconstruction; [Tab](../../backslash/src/cascadia/TerminalApp/Tab.cpp) owns the tree and zoom state. [AppActionHandlers](../../backslash/src/cascadia/TerminalApp/AppActionHandlers.cpp) already handles `SplitPane`, `MoveFocus`, `ResizePane`, `TogglePaneZoom` and `ClosePane`.

Candidate commands should map those facilities: split side-by-side (vertical divider / Right), split stacked (horizontal divider / Down), focus left/right/up/down, resize the focused boundary, maximize/restore the focused pane, and close/rebalance. State divider direction explicitly rather than relying on ambiguous horizontal/vertical wording. Preserve native keyboard actions and audit collisions with shell bindings, selection, accessibility, AltGr/IME and nested tmux. Future file views and other heterogeneous content should implement the existing [IPaneContent](../../backslash/src/cascadia/TerminalApp/IPaneContent.idl) contract and fit the tree, with versioned persistence. Current saved groups support terminal panes only; they do not save file browsers or Settings panes. Remote session survival is separate; optional remote tmux is complementary, not required for local panes.

## Candidate `/files` workflow

Proposed examples: `/files user@hostname-or-IP /remote/path` or `/files saved-ssh-alias "/remote path"`, with an optional explicit local-directory argument. These are design examples, not accepted/executable syntax. No preset should be mandatory. From a local shell context, the left embedded file view represents a reliably established local folder and the adjacent right embedded file view owns connection/authentication and the requested remote directory. Both are file views, not additional shells masquerading as browsers; preserve existing shell access/focus.

If local cwd is unknown, stale or actually remote, show an explicit folder picker/default choice rather than guessing. An SSH pane's cwd is not the local folder; ask for local origin/override. Omitted remote directory should use the server's authenticated default/home directory, with the actual resolved location shown, not a fabricated path. Define host/IPv6/port/alias parsing, quoting/spaces and platform path semantics. Reuse available SSH config/key/agent capabilities where supported, otherwise prompt securely in the right pane; never include passwords in commands/history, autoaccept unknown host keys or bypass changed-key errors. Opening views and transferring selected files are distinct actions. Cancel/failure/retry preserves local view/shell and typed target; retry is explicit. See the [file-transfer design](FILE-TRANSFER-DESIGN.md).

## Delivery phases and tests

1. Inventory action IDs/typed arguments and define dedicated field ownership, quoting, unknown/literal behavior, target preview and accessibility; provide `/help` from that inventory.
2. Reuse palette/dispatch for local Settings, saved-group and profile actions. Add typed group/profile ID validation, action completion, race handling and consistent menu/shortcut behavior.
3. Add supported native pane commands. File views and resumable sessions remain separately gated backend projects.
4. Only after shell-specific/SSH ownership proofs, consider optional inline slash syntax with explicit opt-in and literal bypass.

Acceptance fixtures: exact-name executable collisions; unknown commands; quoted group/profile names; rename/delete while completing; focused SSH vs local ownership; password/full-screen/paste/IME/selection exclusions; Enter once/Escape focus restore; two panes versus two tabs; resize/zoom/close/rebalance; disabled/missing profiles; no connection during preview; explicit file authentication/cancel; unsupported backend errors. No commands are executed by this document. App-command history/telemetry should default to no raw text or secrets; preserve original shell history and command buffers. File/authentication arguments and remote session logs require their separate storage/retention contracts. Prefix, literal syntax, default shortcut, argument grammar and final action coverage remain open.
