# SFTP implementation checkpoint

2026-10-30: user requested actual SFTP for Preview 3, with release preparation after implementation and independent review. This checkpoint is backend groundwork, not a usable Transfers feature or release candidate. No commit, package, tag, push, connection, credential/configuration modification or user-server operation was performed.

Transport choice: independent OpenSSH subsystem process with binary SFTP v3. This preserves SSH alias/config evaluation rather than inventing a second SSH authentication engine. Mandatory initial policy is BatchMode=yes, StrictHostKeyChecking=yes, UpdateHostKeys=no, no TTY/forwarding, RemoteCommand=none. First scope supports existing noninteractive key/agent authentication and pretrusted hosts, not password/keyboard-interactive prompts or host enrollment. Saved-profile parsing must validate owned metadata and supported options before invoking the transport; never execute a profile's arbitrary command line. Respect supported config options, disclose safety overrides and reject unsupported profiles visibly.

Added SftpProtocol.h (bounded packet/request/attribute handling, directory enumeration, binary chunks, exclusive remote creates, rename capability), SftpProcess.h (explicit executable/argv, inherited-handle whitelist, owned kill-on-close child job, stderr draining without retaining server diagnostics), SftpTransfer.h (progress/size/cancellation checked transfer loops into temporary destinations). These headers are not yet included in application production paths. No backend is marked Ready.

Strict /W4 /WX native fixture pass: artifacts/sftp/protocol-fc502704adbc40068f1d05f24c93d0c1. Tests use fake exact-byte streams only: initialization, binary payload/EOF, directory attrs, upload acknowledgment, permission denial, mismatched request identity, oversize/truncation, unknown attrs, download size/progress, cancellation before I/O, unsupported overwrite refusal and Windows trailing-backslash argument quoting. Reproduce with backslash/tools/backslash/Test-SftpProtocol.ps1. Initial quoting test literal failed compilation and was corrected; it was a fixture issue, not a passing run. Process header compilation is not child-process runtime validation.

Next bounded stage: fake child-process transport fixture with watchdog/deadline, cancellation and teardown checks; strict saved-profile resolver (alias versus resolved endpoint, executable selection and unsupported options); real local filesystem adapter with exclusive temp ownership and reparse checks; process-owned jobs and publication state machine with explicit overwrite/retry and retained-partial outcomes. Then wire compact local/remote browser controls into existing Transfers native UI and actual progress/cancel/retry. No UI is wired at this checkpoint. Native transport currently has only connect timeout, not an operation inactivity deadline: do not activate it until bounded cancellation/deadline testing is implemented. Review destructor/drain teardown and child descendant ownership in those tests.

Publication must never truncate the final destination before transfer success. Remote replacement requires advertised posix-rename capability and explicit approval; otherwise choose a new name. Local commit needs its own guarded atomic publication. Failure/cancel may leave owned temporaries; report exact retained state, never blindly resume or delete unrelated paths. Current size checks are not checksums or protection against same-size concurrent source changes. Real authentication/trust/error and local-to-test-server acceptance remain future explicit live-test gates.

## Stage 3: integrated native workspace and process-owned jobs

Implemented `SftpService.h`, `SftpNativeSession.h` and `SftpWorkspaceView.h`, and wired the current Transfers content/template. The native workspace has local/remote path browsing, folder navigation, selected single-file upload/download, optional destination filename, byte progress/results, per-job cancel/retry, search/status filtering, and explicit local replacement confirmation (Cancel default). Browsers are side-by-side at wide logical widths and stacked with page scrolling at narrow widths. A visually clipped narrow action was corrected to Stop with its complete accessibility name/tooltip. Existing Transfers placement/lifecycle remains in place; Close unsubscribes the view and does not cancel process-owned jobs. No release package/ZIP/tag/commit/push was prepared.

The service serializes operations with immutable request snapshots, suppresses stale canceled browser generations, tags browser results with their connection plan, and denies transfers from edited-but-unbrowsed directory fields. Changing selected connection clears incompatible browser rows. Disabling settings rejects new work but leaves existing operations running. Retry creates a new job and cannot reuse an earlier replacement token. An AwaitingDecision token holds the exact local destination plus its locked ancestors; replacement approval applies once to that object. Cancellation before Publishing wins; after publication starts it is rejected and the publication result wins. The process owns jobs/history (bounded preview history); it does not persist a queue across quitting.

Local physical replacement moves the exclusively held original aside, publishes the temporary without replacing any intervening file, and retires only that owned backup. Failure attempts non-overwriting restoration. Structured job fields separately record `published` and retained local/remote artifacts. Successful publication followed by cleanup failure is Completed with a warning and exact retained backup path, not Failed. Restore failure reports the original backup and blocks blind Retry. Canceled uploads retain the exact remote temporary path and unconfirmed cleanup status even when cancellation text is displayed. The actual job-label formatter is shared with the native UI fixture and displays those paths. Local browsing, upload sources and temporaries lock ancestor directories against write/delete sharing and reject reparse, UNC/device and mapped-network paths; first scope is local fixed/removable/RAM drives.

Remote overwrite is deliberately NOT offered: SFTP v3/posix-rename does not supply an identity-bound compare-and-replace primitive. Existing remote destinations require a new filename; no implicit truncation or forced replacement occurs. Remote publication uses non-overwriting rename from an exclusive randomized temporary. Cancellation/disconnect may retain that temporary, with no speculative deletion/resume. Existing key/agent authentication and already trusted hosts are required; password/keyboard-interactive enrollment is unsupported. OpenSSH config evaluation/real-host behavior is not established by fake fixtures. The native code starts a separate owned OpenSSH subsystem for each browser/transfer operation; it does not reuse a terminal or SSH multiplex master. Source size checks are not cryptographic checksums or protection against same-size remote edits.

## Host shutdown drain correction

Implemented the release-blocking owner-process barrier. `AppLogic.{idl,h,cpp}` now exposes asynchronous BeginTransferShutdown plus nonblocking TransferShutdownComplete/status/timeout methods from TerminalApp.dll, where the real SharedService is instantiated. The final owner message-loop exit calls that gate before session persistence/icon cleanup and the upstream TerminateProcess. The handoff-only non-owner exit remains unchanged. The bridge returns drained only after the worker's real OS thread is signaled and joined, not merely Busy=false; this includes pending observer and captured overwrite-authority destructors. Begin rejects new work, cancels pre-publication operations, and preserves an already-started publication. No automatic force happens on deadline/bridge failure.

Each wait has a 35-second budget and pumps STA COM/window work. COM-wait failures use a small sleep rather than spinning. A timeout marks publication uncertainty and presents an owned-process warning with default No (keep waiting), current status/possible artifact paths and an explicit force question. Only accepted force permits unconfirmed termination; that exit returns ERROR_TIMEOUT, not zero. A later confirmed successful publication can clear uncertainty truthfully. Lost publication acknowledgments are classified unconfirmed, never Completed, and cannot blindly Retry. Forced OS/crash shutdown outside this gate is not guaranteed recoverable.
